# 日常检查器 (DailyChecker)

玻璃风格的桌面监控程序（PySide6），与「自动化更新器」同套 UI 框架。
功能移植自 OneDragon ScriptChainer 的 `检查日常.py`。

## 功能

- **日常检测**：20 款游戏逐个扫描日志，判断当日日常是否完成
- **判定规则库**（v1.3.0）：规则 = 「怎么算完成」（判定方式 + 关键字 / 文件名），
  游戏只决定「看哪个日志目录」。一条规则可被多款游戏共用（如 MAA 系 14 款游戏
  共用「任务已全部完成！」），改一次全部生效；新游戏添加时直接从库里选规则，
  库里没有就先建一条。五种判定方式：
  - 关键字（不限日期）—— 与原脚本一致
  - 关键字（仅今天的日志）—— 只搜今天修改过的日志，避免读到昨天的成功记录
  - 今天有新日志 —— 只要存在今天修改的日志文件即算完成
  - 特定文件已生成 / 特定文件今天生成 —— 比指定文件名（可指定是否今天生成）
- **异常监控**：遍历 `D:\Automate\My-maawork`，发现 `on_error` / `screencap`
  文件夹即标记异常，按自然日统计每个游戏连续无错天数
- **存疑判定**：My-maawork 游戏的 debug 目录顶层 `.log` 合计体积超过阈值
  （默认 7MB，FGO 21 / 潮汐守望者 16 / 钢岚 12，可右键单改）
- **钉钉通知**：异常监控 / 存疑提醒 / 日常检测 / 日常汇总 四条消息，
  手动发送前可预览；定时检查后可自动发送
- **排除管理**：不想检查的游戏右键排除（不参与日常 / 异常 / 无错天数）
- **数据目录可自选**：默认 `D:\Automate\Cache`，与原脚本共用
  `error_detect_state.json`，无错天数连续不重计

## 设置页 · 检查参数与判断方式（v1.1.0）

- **检测 on_error / screencap 文件夹**开关：关闭后跳过文件夹异常扫描
  （日常失败仍会清零无错天数）
- **单游戏阈值覆盖 / 文件夹关键词映射 / 排除的游戏**
  三个行都有「管理…」入口，可批量逐个调整（判定规则已独立成页，见 v1.3.0）
- **文件夹关键词映射**：My-maawork 程序文件夹名 → 游戏显示名，
  内置 13 条默认映射，可追加或覆盖（用于异常监控与无错天数统计）

## v1.2.0 新增

- **游戏列表独立页**：侧边栏 总览 / 游戏列表 / 设置（Ctrl+1/2/3）；
  总览为统计卡片 + 关注摘要，列表在独立页
- **排序方式**（列表页右上角下拉）：默认顺序 / 按名称 / 无错天数 / 日志大小 /
  未完成优先 / 异常优先 / **手动拖拽**（按住游戏行拖动调整顺序，自动持久化）
- **多判断方式**：右键「设置判断方式」可勾选多种方式，任一满足即算完成
- **新增判断类型**：特定文件已生成 / 特定文件今天生成
  （在判断方式对话框里填目标文件名，相对日志目录）
- **异常标签**：检测到 on_error / screencap 时，行上直接显示对应文件夹名标签
- **行按钮**：每行「目录」（程序根目录）+「日志」（日志文件夹）
- **默认日志阈值改为 10MB**
- **通知方式**：设置页选择 不通知 / 钉钉机器人，选钉钉才显示钉钉配置项
- **命令行参数**：
  - `--check` 启动后立即检查一轮（不自动发通知）
  - `--notify` 检查后发送钉钉通知（配合 --check）
  - `--quit-after` 检查/通知完成后自动退出（配合计划任务）
  - `--hidden` 后台静默启动
  - 例：`DailyChecker.exe --check --notify --quit-after --hidden`

## 使用

- `DailyChecker.exe` 便携运行，配置生成在 exe 同目录 `config/config.json`
- 开机自启 / 定时检查 / 关窗驻留托盘均在设置页
- 快捷键：Ctrl+1/2/3/4 切页，F5 开始检查

  「文件夹关键词映射 / 规则库 / 游戏 → 规则」，各自独立成页，选中项在侧边栏高亮
- **文件夹关键词映射页展示内置 13 条映射**：卡片式两列排列，一眼能看到哪个文件夹名对应哪款游戏；
  自定义映射仍走「管理…」
- **换上专属应用图标**：青绿渐变 + 白色对勾，和自动更新器的紫色箭头图标区分开

## v1.4.0 更新

- **日志阈值搬到「判定规则」页的游戏行上**：每款游戏那一行右侧直接有「日志阈值」步进器，
  改完即时生效，不用再进设置页翻一遍名单。设置页只留一个「默认日志阈值」
- **默认阈值统一成 10MB**：新装机（或还没单独设过的游戏）一律 10MB；以前给 FGO / 潮汐守望者 /
  钢岚 单独调过的 21 / 16 / 12MB 不动，视为手动设置。把某款改回 10MB 就等于「跟随默认」
- **关注列表两列排整齐**：之前每格宽度按内容算、行高被拉伸，左右两列错位；现在两列等宽、
  行高固定 34px、顶部对齐，卡片多出来的高度由底部空白吸收
- **修好换行文字被裁掉**：窗口变窄时「引用游戏：…」「匹配规则：…」折成两行只显示一行，
  第二行被切掉半截字。QLabel 本来就实现了 heightForWidth，但默认 sizePolicy 没声明支持，
  布局只按单行算高度。新增 `widgets.WrapLabel`，按实际宽度同步最小高度
- 「文件夹关键词映射」从设置页移到判定规则页底部（和规则、游戏放一起）
- 「规则库 · N 条 / 游戏 → 规则 · N 款」两个分区标题字号 12 → 15

## v1.3.1 更新

- **修好提示气泡（tooltip）变黑底灰字**：鼠标悬停在「匹配规则」「日志目录」这类文字上
  弹的提示框，之前底色是纯黑、字是深灰，几乎看不清。原因是给文字上色时用的是不带选择器的
  样式，Qt 里提示框窗口是那个控件的子窗口，会把 `background: transparent` 一起继承过去，
  把 `QToolTip` 的白底抹掉了。现在所有内联样式都套一层 `#objectName` 作用域，
  只作用于控件自己；提示框恢复成「主题底色 + 正文色」（深色主题下是深底浅字）
- 顺带把两个项目共用的样式工具抽成 `theme.tint() / theme.flat() / theme.scoped()`，
  以后给控件上色不会再踩这个坑

## v1.2.4 更新

- **修复启动时弹出小窗口并疯狂闪烁**：构建设置行 / 判断方式行时，
  描述文字和文件名输入框在还没加入布局（没有父级）时就被 `setVisible(True)`，
  Qt 会把它当成独立顶层窗口弹出来（带标题栏的空白小窗），
  启动检查、切换主题、翻页时反复重建就会连续闪。

  不再 `setParent(None)`（控件脱离父级同样会变成顶层小窗）
